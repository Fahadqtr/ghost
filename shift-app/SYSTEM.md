# نظام إدارة الورديات — قسم العمليات الجمركية

توثيق كامل للنظام: الوظائف، الأدوار، الشاشات، البنية التقنية، وقاعدة البيانات.

---

## 1. نظرة عامة

تطبيق ويب (PWA) لإدارة ورديات الموظفين في قسم العمليات الجمركية، يعمل على الجوال والكمبيوتر، بواجهة عربية (RTL). البيانات مشتركة ومتزامنة لحظياً بين كل الأجهزة عبر Supabase، مع نسخة محلية للعمل دون إنترنت.

- **الرابط:** https://fahadqtr.github.io/ghost/
- **رابط الموظفين (عرض فقط):** أضف `?staff` إلى الرابط، أو استخدم رمز QR من لوحة المعلومات.
- **التقنية:** JavaScript خالص بدون خطوة بناء (no build step) + Supabase (Postgres + Auth + Realtime).
- **النشر:** GitHub Pages من مجلد `shift-app/` عبر GitHub Actions (مع كسر التخزين المؤقت `?v=<git-sha>` لكل نشرة).

---

## 2. الأدوار والصلاحيات

| الدور | من هو | الصلاحية |
|------|-------|----------|
| **رئيس القسم** (`owner`) | المدير العام | يرى ويدير **كل الورديات**؛ يضيف/يحذف ورديات؛ يعتمد الكشوفات؛ يرسل تعاميم؛ يتابع كل شيء. |
| **مسؤول الوردية** (`admin`) | مشرف الوردية | يدير **ورديته فقط**: الموظفون، الجدول، الإجازات، الكشوفات، النقطة، توجيهات موظفيه. |
| **موظف** (`viewer`) | أي موظف | **عرض فقط**: جدوله، إجازاته، وقت استلام النقطة، التعاميم والتوجيهات الموجّهة له. يطلب إجازة (بانتظار الاعتماد). |

**تسجيل الدخول:**
- المشرفون ورئيس القسم: باسم مستخدم وكلمة مرور (يُكمَّل داخلياً بنطاق `@shift.local`).
- الموظفون: بالرقم الوظيفي فقط (صفحة `?staff`) — دخول سريع بصلاحية عرض.

---

## 3. عزل بيانات الورديات (نظام متعدد الورديات)

نظام واحد ورابط واحد يخدم عدة ورديات دون اختلاط البيانات:

- كل صف بيانات موسوم بعمود `team` (رمز الوردية: `w1`, `w2`, ...).
- **سياسات الحماية (RLS)** على مستوى قاعدة البيانات تضمن أن كل مشرف يرى ويعدّل بيانات ورديته فقط، ولا يستطيع قراءة أو الكتابة في وردية أخرى.
- **رئيس القسم** له صلاحية شاملة عبر كل الورديات (يُتحقّق منها من قاعدة البيانات مباشرة عبر دالة `is_owner()`).

## 4. الشاشات والوظائف

### 4.1 لوحة المعلومات (الرئيسية) — للمشرفين ورئيس القسم
- حالة اليوم: عدد العاملين، المُجازين، إجمالي الموظفين، الطلبات المعلّقة.
- طلبات الإجازات بانتظار الاعتماد (اعتماد/رفض).
- جدول المستلمين على النقطة اليوم.
- إجازات الوردية القادمة، وإجازات تبدأ خلال ٧ أيام.
- عدالة توزيع الإجازات (رسم بياني لكل موظف).
- توزيع ورديات اليوم (صباح/عصر/ليل/راحة).
- روابط ورمز QR لدخول الموظفين.
- أزرار: إضافة إجازة، توجيه للموظفين، تحديث.

### 4.2 لوحة رئيس القسم (تظهر لرئيس القسم فقط أعلى الرئيسية)
- **اسم رئيس القسم:** يُحفظ ويُبثّ لكل الورديات، ويظهر في اعتماد الكشوفات.
- **الوردية المعروضة الآن:** قائمة اختيار لتبديل الوردية التي يتابعها.
- **إضافة وردية جديدة:** تُنشئ إعدادات مستقلة + حساب مشرف للوردية.
- **تعديل بيانات الوردية / حذف الوردية.**
- **إرسال تعميم للمسؤولين.**
- **متابعة جميع الورديات:** لكل وردية (عدد الموظفين، المُجازون اليوم، الطلبات المعلّقة، النقاط المعتمدة) وزر «فتح».

### 4.3 الموظفون
- تسجيل/تعديل/شطب موظف (الاسم، الرقم الوظيفي، بداية دورة العمل).
- حالة كل موظف اليوم (وردية/راحة/إجازة).

### 4.4 الجدول
- جدول شهري لكل الموظفين: دورة عمل/راحة (افتراضياً ٦ عمل / ٤ راحة) تتوالى (صباح ← عصر ← ليل).
- تعديل يدوي لأي خانة (يتجاوز الدورة والإجازات).
- ملخّص التغطية اليومية (عدد كل وردية + إجمالي العاملين مع تنبيه عند أقل من الحد الأدنى).
- أزرار: اليوم، أقرب وردية.
- **للموظف:** عرض فقط + بطاقات التعاميم والتوجيهات أعلى الشاشة.

### 4.5 الإجازات
- إضافة إجازة: النوع (سنوية، عارض، دورة تدريبية، مرضية، مرافق مريض، غياب)، الفترة، الحالة، ملاحظات.
- اعتماد/رفض الطلبات.
- **للموظف:** عرض إجازاته + تقديم طلب إجازة جديد (يظهر «قيد الانتظار» عند المشرف).

### 4.6 كشف يومي (كشف الحضور والانصراف) — مخفي عن الموظفين
- كشف رسمي مطابق للنموذج: شعار QATAR CUSTOMS، صندوق عنوان، جدول بكل الموظفين، صندوقا توقيع (مسؤول الوردية / رئيس قسم العمليات الجمركية).
- تعديل توقيتات الدخول/الخروج قبل التنزيل (قوائم اختيار كل نصف ساعة).
- **اعتماد رئيس القسم:** عند الاعتماد يظهر اسمه وعلامة «معتمد ✔» في خانة التوقيع.
- **تنزيل ملف Word حقيقي**، مشاركة كصورة (واتساب)، طباعة/حفظ PDF.
- **لرئيس القسم:** مبدّل وردية أعلى الشاشة لتصفّح كشوفات كل الورديات وتنزيلها مباشرة.

### 4.7 النقطة الأمنية (استلام النقطة)
- توزيع الموظفين على النقطة ليوم/وردية: يُقسَّم وقت الوردية بالتساوي إلى فترات متتالية.
- إضافة/إزالة/ترتيب الموظفين، ثم الاعتماد.
- المُعتمِد يُسجَّل (مسؤول الوردية / مساعد) + رئيس القسم.
- تنزيل كشف Word ومشاركة كصورة.
- **للموظف:** يرى فترته ومن يستلم منه (شاشة منبثقة عند الدخول).
- **لرئيس القسم:** مبدّل وردية أعلى الشاشة.

## 5. التعاميم والتوجيهات

### التعاميم (من رئيس القسم)
- يرسلها رئيس القسم فتُبثّ **لكل الورديات**.
- خيار الجمهور: **«للمسؤولين فقط»** أو **«لكل الموظفين والمسؤولين»**.
- تظهر في **شاشة منبثقة** عند الدخول + **بطاقات صغيرة** (تُفتح بالنقر إلى النص الكامل) في الرئيسية (للمسؤولين) وشاشة الجدول (للموظفين إن كانت موجّهة للجميع).
- رئيس القسم: حفظ/حذف أي تعميم أو مسح الكل (يُحتفظ بآخر ٣٠).

### التوجيهات (من مسؤول الوردية)
- يرسلها المشرف لموظفي **ورديته فقط** (خاصة بالوردية).
- تظهر للموظف في شاشة منبثقة عند الدخول + بطاقة في شاشة الجدول.
- المشرف: إرسال/عرض/حذف/مسح الكل.

**ترتيب المنبثقات عند دخول الموظف:** تعميم رئيس القسم (للجميع) ← توجيه مسؤول الوردية ← وقت استلام النقطة (واحد لا يحجب الآخر).

## 6. التثبيت والعمل دون إنترنت (PWA)

- قابل للتثبيت كتطبيق على الجوال (شريط تثبيت + تعليمات iOS).
- Service Worker بسياسة «الشبكة أولاً»: أحدث نسخة دائماً، والنسخة المخزّنة عند انقطاع الإنترنت.
- طابور محلي (Outbox): التعديلات تُحفظ محلياً وتُرسَل تلقائياً عند عودة الاتصال.
- مؤشر المزامنة: متزامن / مزامنة… / غير متصل.

## 7. البنية التقنية

### ملفات المشروع (`shift-app/`)
| الملف | الوظيفة |
|------|---------|
| `index.html` | الهيكل، شاشتا الدخول، شريط التنقّل، ترتيب السكربتات. |
| `styles.css` | التنسيق (ثيم عنّابي/Maroon)، قواعد إخفاء تبويبات الموظف، تنسيق الطباعة. |
| `config.js` | رابط Supabase والمفتاح العام (publishable). |
| `cloud.js` | طبقة المزامنة: الدخول، RLS، `pull`/`apply`، الطابور المحلي، دوال RPC. |
| `qr.js` | مولّد QR محلي (بدون إنترنت) على canvas. |
| `app.js` | منطق التطبيق والواجهة وتوليد ملفات Word. |
| `seed.js` | بيانات ابتدائية (تُستخدم أول تشغيل فقط). |
| `sw.js` | Service Worker. |
| `manifest.webmanifest` | بيان تثبيت التطبيق. |

### توليد ملف Word (.docx)
يُبنى ملف Word حقيقي في المتصفح: حزمة ZIP يدوية (تخزين + CRC32) + WordprocessingML (جداول، دمج خلايا، اتجاه RTL، ترويسة بشعار مضمّن كصورة). يعمل عند فتحه على الجوال والكمبيوتر.

### المشاركة كصورة
`html2canvas` (يُحمّل عند الحاجة) لتحويل الكشف إلى صورة PNG ثم مشاركتها عبر `navigator.share` (واتساب) أو تنزيلها.

## 8. قاعدة البيانات (Supabase)

**المشروع:** `shift-scheduler` — منطقة `eu-central-1`.

### الجداول (schema: `public`)
| الجدول | الوصف | أعمدة رئيسية |
|-------|-------|-------------|
| `employees` | الموظفون | `id, name, emp_no, cycle_start, sort_order, team` |
| `leaves` | الإجازات | `id, emp_id, type, from_date, to_date, status, notes, team` |
| `overrides` | تعديلات الجدول اليدوية | `emp_id, day, value, team` |
| `settings` | إعدادات كل وردية (JSON) | `id, team, data` |
| `point_shifts` | توزيع النقطة | `team, day, shift, emp_order, approved, approved_by, approved_title, point_name` |

`settings.data` (JSON) يحوي: القسم، أطوال الدورة، الحدود، أوقات الورديات، أنواع الإجازات، ترويسة الكشف (الموقع/اسم الوردية/المشرف/المساعد)، الشعار، `deptHead` (اسم رئيس القسم)، `dailyApproved` (اعتماد الكشوفات)، `notices` (التعاميم)، `directives` (التوجيهات).

### المصادقة (Auth)
- بريد/كلمة مرور. حسابات المشرفين: `username@shift.local`. حسابات الموظفين: `e<الرقم الوظيفي>@shift.local` وكلمة المرور = الرقم الوظيفي.
- `app_metadata`: `role` (`owner`/`admin`/`viewer`) و`team`.

### سياسات الحماية (RLS)
لكل جدول سياستان (قراءة/كتابة):
- **قراءة:** `is_owner()` **أو** `team = وردية المستخدم`.
- **كتابة:** `is_owner()` **أو** (`admin` **و** الوردية مطابقة).
- الموظف: سياسات خاصة تتيح له تقديم/تعديل/حذف طلب إجازته «قيد الانتظار» فقط.

> **ملاحظة مهمة:** التحقق من صلاحية رئيس القسم يتم عبر دالة `is_owner()` التي تقرأ الدور **من قاعدة البيانات** (لا من رمز الجلسة) — لتفادي مشكلة قِدَم الرمز (JWT).

### الدوال (RPC — SECURITY DEFINER)
| الدالة | الوظيفة |
|-------|---------|
| `is_owner()` | تُعيد هل المستخدم الحالي رئيس قسم (من `auth.users`). |
| `create_team(name, admin_user, admin_pass, admin_name, assistant)` | تُنشئ وردية `w<N>` + إعداداتها + حساب مشرفها (لرئيس القسم فقط). |
| `delete_team(team)` | تحذف وردية بكل بياناتها وحساباتها (لرئيس القسم فقط، عدا `w1`). |
| `owner_broadcast(patch)` | تدمج حقولاً مشتركة (اسم رئيس القسم/التعاميم) في إعدادات كل الورديات (لرئيس القسم فقط). |

> **ملاحظة:** يمنع امتداد `safeupdate` أي `UPDATE` بلا شرط `WHERE`؛ لذا تحدّث `owner_broadcast` بشرط `where team is not null`.

## 9. منطق الجدول

- تبدأ دورة كل موظف من `cycle_start` الخاص به.
- نمط الدورة: `workDays` أيام عمل تتوالى فيها الورديات (كل يومين تتغيّر: صباح→عصر→ليل بدءاً من `startShift`)، ثم `restDays` أيام راحة.
- الإجازات المعتمدة تظهر مكان الوردية.
- التعديل اليدوي (`overrides`) يتجاوز كل ما سبق.

---

## 10. كيفية إضافة وردية جديدة (لرئيس القسم)

1. الدخول بحساب رئيس القسم.
2. من لوحة رئيس القسم ← **«＋ إضافة وردية»**.
3. إدخال: اسم الوردية، اسم مستخدم المشرف وكلمة مروره، اسم المشرف، والمساعد (اختياري).
4. يُنشأ للوردية بياناتها المستقلة وحساب مشرفها؛ ثم يُسلَّم المشرف بياناته للدخول وإدخال موظفيه.

---

## 11. ملاحظات أمنية

- المستودع عام؛ لذا **الشعار الرسمي** يُخزَّن في إعدادات Supabase الخاصة فقط، لا في المستودع.
- المفتاح المستخدم في `config.js` هو المفتاح **العام** (publishable) المخصّص للواجهات، والحماية الفعلية عبر RLS.
- كلمات المرور لا تُوثَّق ولا تُحفظ في المستودع.
